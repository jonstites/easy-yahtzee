  Per-die keep toggle + one "Roll" button + per-choice "Apply" button. Put a
  small checkbox/lock under each die to mark it kept (face-cycling on click
  stays as-is, so manual entry from a physical game still works). A single
  "Roll" button re-rolls the non-kept dice and advances roll 1→2→3; on roll 3 or
   when all 5 are kept, it becomes disabled. Each row in the ranked list gets an
   "Apply" button: for keep rows it sets the keep toggles to match and rolls;
  for score rows it writes the scored value into the scorecard, resets
  dice+roll, and moves on.

  Tradeoff: the dice get a bit busier (face-cycling + keep toggle both live on
  each die). Alternative is a mode switch ("entry mode" vs "play mode") that
  keeps the dice UI minimal but adds a top-level control. I'd default to the
  first since it keeps both workflows one click away.

● Honest take: I like the instinct, but I'd only go partway. Full paper-sheet
  mimicry has two costs — widening the card to fit a "How to Score" column
  squeezes our already-tight left grid, and going pure B&W loses the warm cream
  tone that's currently holding the whole page together. You'd end up with a
  high-contrast island next to a soft page.

  What I'd actually do:

  1. Add cell borders to the scorecard so it reads as a true grid (like the
  paper sheet), not a stack of lightly underlined rows.
  2. Tiny pip icon next to Ones/Twos/...Sixes — cheap thematic win.
  3. "How to score" column, but short — "count 1s", "25", "30", "40", "sum",
  etc. (not full sentences). Muted text so it doesn't fight the entry names.
  4. Replace the cream Upper subtotal / Upper bonus rows with the sheet's arrow
  idiom → and a value cell — more scorecard-like and kills the last cream tint.
  5. Keep the blue left-border accent on the best row — it's functional (the
  engine's suggestion) and reads as "annotation" over the sheet, not as
  decoration.
  6. Drop the olive on "UPPER"/"LOWER" section labels → plain bold black.

  Tradeoff: makes the sheet feel more like the real thing, but we inherit some
  of its density. Works only if we keep the "How to score" column restrained
  (one short phrase each, tiny font) — otherwise it eats horizontal space.

  Review of things I'd improve (ordered by impact):

  UI
  1. "Roll" label + 1/2/3 segmented + Roll button + Randomize on one line is 
  busy. The "Roll" label is redundant with the Roll button right beside it. Drop
   the label; the segmented control reads as a state pill.
  2. Keyboard shortcut for Roll (Space) and Apply-top (Enter). For rapid
  simulation it'd feel great. Focus management is the only wrinkle (don't
  trigger while typing scores).
  3. Empty-space on the right side when choices are few or during game-over.
  Could pin dice/choices panel higher or add a quiet footer ("engine: DP solver
  · 1M states" / link to repo).
  4. The "keep" text repeats 5 times. Could show "Keep →" once on the left and
  use just checkboxes, but I'd actually leave it — explicit is kinder.
  5. Dice cycling on click isn't discoverable. Tooltip is there but invisible
  until hover. A tiny ↕ cursor hint or a one-line caption "click dice to edit"
  below the row would help — but risks clutter. I'd add it faintly once as
  first-time tutorial, or not at all.

  Code (App.svelte is ~900 lines now)
  1. Split into components. Scorecard.svelte, DicePanel.svelte,
  ChoiceList.svelte, GameOver.svelte, Totals.svelte. Each would be 50–200 lines
  and have obvious ownership. Biggest maintainability win.
  2. Extract the Undo/Snapshot logic into a small module or Svelte store —
  decouples history from the view.
  3. Some magic numbers (grid column widths, die sizes) could become CSS vars
  for consistency.
  4. PIP_POS and dice SVG markup appear twice (main dice + mini-die + new
  pip-icon); could be a reusable <Die size={} face={}/> component.

  From Verhoeff's site
  - Honestly, mostly not to copy — it's dense and math-y, we're cleaner. But one
   genuine idea: they show EV with ±stddev (e.g. 268.25±23). That uncertainty
  info is real and we throw it away. Could be a nice advanced-mode thing.
  - Their "turn #N" at the top-left is a reasonable alternative home for our
  turn counter, but I think the bottom footer works fine.
  - Their free-form die value dropdowns (Value + Keep as two separate controls
  per die) are what we already converged on — good sign.

  What I'd actually do next, in order: (a) component split, (b) drop the
  redundant "Roll" label, (c) keyboard shortcuts. The rest is polish. Want me to
   take any of these?
